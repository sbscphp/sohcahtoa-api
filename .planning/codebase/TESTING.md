## Mocking

**Framework:**
- Jest built-in mocking (no external mock library detected)
- `jest.mock()` for module mocking
- `jest.spyOn()` for spying on methods

**Patterns:**
Would follow this pattern based on service structure:

```typescript
// Mock Prisma
jest.mock('../config/database', () => ({
  __esModule: true,
  default: {
    settlement: {
      findUnique: jest.fn(),
      create: jest.fn(),
      update: jest.fn(),
    },
    exchangeRate: {
      findFirst: jest.fn(),
    },
  },
}));

// Mock Redis
jest.mock('../config/redis', () => ({
  __esModule: true,
  default: {
    get: jest.fn(),
    setex: jest.fn(),
  },
}));

// Mock Kafka
jest.mock('../config/kafka', () => ({
  publishEvent: jest.fn(),
}));
```

**What to Mock:**
- External dependencies: Prisma database calls
- Cache layer: Redis operations
- Message queue: Kafka publish/subscribe
- External services: Email, SMS, verification APIs
- HTTP clients: Axios or node-fetch calls to other microservices

**What NOT to Mock:**
- Utility functions: password hashing, JWT generation, validators
- Error classes: test actual error throwing behavior
- Response formatters: test actual response structure
- Business logic: test actual algorithm implementation

## Test Types

**Unit Tests:**
- Scope: Individual functions/methods in isolation
- Approach: Mock all dependencies (database, cache, external APIs)
- Location: Next to implementation files
- Example services to test:
  - `apps/payment-service/src/services/payment.service.ts` - test each method
  - `apps/auth-service/src/services/auth.service.ts` - test signup, login, KYC flows
  - `apps/admin-service/src/services/admin.service.ts` - test approval/rejection workflows

**Integration Tests:**
- Scope: Multiple services working together via Kafka events
- Approach: Real or test containers for Kafka, real or in-memory database
- Would test event publishing/consuming between services
- Example: Auth service publishes USER_CREATED event, Transaction service consumes it
- Not currently implemented

**E2E Tests:**
- Framework: Not detected
- Would typically use: Jest with supertest for HTTP endpoints
- Example: POST /api/auth/signup → verify response and database state
- Not currently implemented

## Common Patterns

**Async Testing:**
```typescript
it('should fetch exchange rate', async () => {
  const rate = await paymentService.getExchangeRate(request);
  expect(rate).toEqual(expect.objectContaining({
    fromCurrency: 'USD',
    toCurrency: 'NGN',
  }));
});
```

**Error Testing:**
```typescript
it('should throw NotFoundError when exchange rate not found', async () => {
  prisma.exchangeRate.findFirst = jest.fn().mockResolvedValue(null);

  await expect(
    paymentService.getExchangeRate(request)
  ).rejects.toThrow(NotFoundError);
});

it('should throw ValidationError for invalid input', () => {
  expect(() => {
    validateEmail('invalid-email');
  }).toThrow(ValidationError);
});
```

**Spying on External Calls:**
```typescript
it('should publish event to Kafka', async () => {
  const publishEventSpy = jest.spyOn(kafka, 'publishEvent');

  await paymentService.initiateDeposit(data);

  expect(publishEventSpy).toHaveBeenCalledWith(
    expect.objectContaining({
      eventType: EventType.TRANSACTION_CREATED,
    })
  );
});
```
